# I retain checked affine identifier uses

I extend #998 beyond function-level checker completion with an explicitly bounded per-use source fact. My initial slice records an ordinary resource identifier use that the existing ownership checker accepts as observing or consuming its lexical binding. It does not infer a use from bytecode, ownership tables, syntax alone, or advisory function metadata.

I initialize retained identifier facts to UNKNOWN in both parser representations. The actual existing resource checker records OBSERVE or CONSUME only after its binding-state, boundary and borrow-conflict checks succeed. Emission additionally requires successful completion of the containing source function checker. Generic/shared-AST instances, synthetic functions, raw unchecked source and unsupported use shapes remain UNKNOWN; they cannot borrow another instantiation's retained result.

I invalidate stale facts with a function-owned check epoch. C uses exact AST function identity and its epoch. Nano allocates a fresh one-element integer array as the source function's identity token; identity is observed by a private, nonallocating alias probe, not language equality or a Parser ordinal. The seed evaluator compares array contents while VM/native equality compares handles. My probe validates positive one-cell tokens, saves one cell, writes a reserved transient -2 marker, reads the other cell, and restores the first before returning. These fixed-size primitive accesses cannot invoke callbacks or reenter; -2 is never a persistent token value. Every actual checker entry advances the token epoch, including skipped/failed checks. A separately retained completed epoch must match both the token's current epoch and the identifier's snapshot. This prevents a stale shallow function copy with a formerly true completion flag from validating facts produced by a later failed check on the shared graph. The Nano epoch saturates to a permanently disabled negative sentinel before its generated C integer field can overflow; C likewise disables rather than reusing an epoch.

Parser copies that share the exact source-function/identifier graph may share a token; rebuilt, rebound, generic and synthetic function constructors receive a fresh token or UNKNOWN. Only the exact completion update preserves the source token. Nested functions use independent checked owners or remain UNKNOWN. I audit every function constructor and do not use mutable global checker state. The initial VM/native equality probe did not cover seed-evaluator equality; a real imported shadow exposed that difference. The final alias-probe regression must pass through that evaluator as well as fresh stages and native output.

I use versioned advisory site records with emitted function index, source coordinate provenance and source binding spelling. These identify a source observation, not an authoritative nominal binding or bytecode ownership transfer. Identical spellings never establish identity. Original C source coordinates and flattened Nano compilation-unit coordinates remain explicitly distinct. Unsupported borrowed projections, joins, path summaries, nested captures and generic identity still need separate acceptance.

I must map retained identifier nodes through actual ordinary and resource lowering. A fact may be published only for the exact checked source node of the emitted function; I do not scan unrelated parser nodes into a function. Resource lowering can consume identifiers without ordinary expression emission, so that route requires its own checked mapping. I preserve executable string-index order by appending indexed advisory records after complete executable emission where needed.

I require both producer paths with actual consume/observe fixtures, multiple lexical bindings and source coordinates; raw UNKNOWN and generic UNKNOWN controls; move-after-use, double move and borrow conflict refusals preserving old outputs; canonical transport, malformed/duplicate/allocation codec controls; and unchanged VM/native behavior after strip or forgery. Fresh actual Stage1/Stage2 and Linux/Darwin qualification remain mandatory for closure. This slice alone does not close #998's full path-sensitive affine or broader imported/generic fact obligations.

I implement this bounded owned-identifier slice without using function completion alone as source-use evidence. My C checker also retains some borrowed-reference root observations; my Nano checker conservatively leaves those roots UNKNOWN. I do not claim paired borrowed-root or per-path coverage from the owned-identifier corpus. Fresh aggregate generations and platform qualification remain open.
