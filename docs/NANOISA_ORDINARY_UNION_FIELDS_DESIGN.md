# Ordinary union fields: exact first contract

Status: design for review, with an unchanged-source baseline; no implementation or admission authorization. Base aggregate: `f53539b9c`. I own this finite #1001 checkpoint on `design/5.1-ordinary-union-fields`. [Baseline](evidence/ordinary-union-field-baseline-20261022/README.md).

## Accepted anchor and boundary

The exact first anchor is `union Box<T> { Some { value:T }, None {} }`, `struct Outer { boxed:Box<int> }`, and the unchanged main/shadow constructing Some(42), reading Outer.boxed, matching the variant and returning payload minus42. Six ordinary/independent-shadow modules actually verify and execute VM/native while omitting authority. The first proposed structural profile is one exact nominal union instance with one INT-payload alternative and one empty alternative. Box/Some/None identify the retained anchor, never an authority name allowlist. STRING, nested/resource payloads, recursive unions, multiple generic instances and other source corpus cases are separate obligations, even when the wire grammar can represent them.

C `ordinary_authority.inc` rejects any module with unions before publication; `ordinary_slot_tag` has no TYPE_UNION authority tag. Nano `nisa_ordinary_publication` similarly rejects parser unions. Removing these guards alone is unsound.

## Existing grammar and missing declaration interface

I propose reusing existing complete layouts and kind1 UNION_VARIANTS, not inventing an extension. A concrete candidate for this anchor has union layout0 COMPLETE with flattened named INT payload row0; record layout1 COMPLETE has field0 TAG_UNION referring to layout0. Union ordinal0 maps explicitly to layout0; Some is variant0, offset0/count1, and None is variant1, offset1/count0. Record ordinal0 maps separately to layout1. The current decoder rejects forward TAG_UNION edges even in its mixed mode, so the earlier record-first alternative is unadmitted; I do not widen that decoder. The proposed prior-only byte fixture still requires actual independent common-validator qualification in the declaration phase. Native ordinal/layout identity restrictions are unresolved for this ordering and must remain closed until explicitly qualified. Variant names, payload names, contiguous coverage, reserved zeroes and exact referents must pass the existing independent common grammar checks. Exact emitted layout ordering remains a producer agreement to qualify; operand ordinals must never be substituted with layout indexes.

Common `ownership_contracts.c` can validate a COMPLETE union field referent and the existing variant directory. Current ordinary declaration projection cannot: `ordinary_array_authority.inc` rejects TAG_UNION with a referent, restricts field tags, and requires projected union flags0. `ra_prepare_records` also accepts only the old noncomplete union declarations. Old projection tests cover standalone union rows, not record fields containing complete unions. The first implementation proposal therefore needs a separate opt-in complete-union declaration route. Old NULL/projection routes, diagnostics, sizes and budgets remain unchanged. The new route owns copied descriptors/variant rows and is descriptive only; no executable trusted-plan argument is exposed.

## Nominal binding and producer provenance

Authority must bind the resolved union declaration, its concrete type arguments, the exact variant ordinal and substituted field type. `nb_union_type_identity` already distinguishes declaration owner/source index plus recursive concrete arguments; `nb_union_field_type` and `nisa_union_concrete_field` substitute generic parameters. These helpers are candidates to reuse, not proof that ordinary publication already carries their identity. C `CgUnionDef` registration currently keeps name/variant counts/names/field names/ordinal; that registration alone is not a checked concrete payload-type witness. A later producer design must trace the checked TypeInfo/declaration relation and reject ambiguity or mismatched arguments independently of emitted INT instructions.

Raw Nano entrypoints may parse and lower without the semantic checker. Any future raw publication must explicitly use declaration-bound parsed identity plus actual lowering and full independent candidate query, preserving existing import binding checks. It must not claim checked provenance. Ordinary programs and independently selected shadows have independent candidates and decisions.

## Proof and immutable execution obligations

The existing structure guard requires AGG_PACK kindRECORD with variant0 and excludes UNION signatures. The new route must independently validate all instructions, including unreachable instructions. For this anchor AGG_PACK variant(kind1, union ordinal0, Some0, one INT), AGG_PACK record(kind0, record ordinal0, one union), AGG_GET and AGG_TAG need exact recipes. UNION construction gets a distinct origin kind in the same bounded64 namespace; no runtime pointer is assigned invented static provenance.

Proof must retain nominal union identity, possible variant identities and per-variant historical payload constraints. Field access requires safety for every reachable variant at that program point; AGG_TAG branches may refine only through an explicitly proved relation. The actual raw baseline tests variants with DUP→AGG_TAG→PUSH_I64→EQ→JMP_FALSE; the Some arm stores that same variant and reads AGG_GET0, while None never reads a payload. A selected proof must either establish a conservative origin subset containing only variants with the exact field obligation, or retain an explicit value/tag-test relation through this control flow and refine it on the corresponding branch. If Some and None still reach AGG_GET0 together, the access refuses. Unsupported tag-test patterns cannot be treated as a refinement; `.match_coverage` remains advisory and supplies no authority. None has no payload and cannot satisfy Some.field0 simply because the flattened layout has row0. Joins, calls, tails, globals and detached aliases preserve historical writes and child obligations. Generic AGG_SET can mutate union payload while preserving variant identity; the first slice explicitly refuses union-payload AGG_SET. Ordinary Outer.boxed replacement, if enrolled, requires complete historical variant/alias transfer; it cannot discard detached prior variants. Current shape alone cannot authorize a write. No termination, presence or variant inference from source spelling is permitted.

Copied declaration, plan, image and recipe constructors independently validate correspondences and preserve outputs on failure. A descriptive plan is not execution authority. Transport/load/save/assembler, verifier, VM and native public selection must be wired together after private qualification; malformed selected metadata must never fall back to generic execution. Old absence behavior and bytes remain unchanged. Detailed owning API signatures, allocation capacities and work schedule are prerequisites to any implementation, not established by this design.

## VM ownership and import requirements

Ordinary VM AGG_GET retains the selected value before releasing the receiver; AGG_TAG releases its union receiver and returns INT. Selected consumers must establish exact nominal/variant/tag/count and cumulative retain headroom before mutation. Record→union edges and returned payload lifetime require actual private and borrowed-state/public tests. Ordinary record/union def_idx conventions remain ordinals; copied layout mapping must be explicit. No persistent trusted context is stored in VmState.

Historical global/import obligations must include union alternatives and conjunctive shared-identity constraints. Fresh import must validate ordinary buffered GC state, all readable global capacity, payload counts, nominal mapping and cycles under the declared boundary. It must not normalize metadata or clear globals. Private teardown depth/edge storage needs a separate bounded derivation; existing record/array bounds cannot silently include an extra union chain. Root signature remains the current zero-arity INT entry, with existing initializer constraints. Selected failure unwind, first error, assertion resume, prior aliases/globals and repeated result consumption retain their existing public/private distinctions.

## Native intersection and qualification

Current nvm2c simulation converts AGG_VARIANT payload carriers through OPTIONAL scalar/INT-array shapes; emitted AGG_TAG checks AGG_VARIANT kind, and legacy nrec_snapshot paths remain. These are legacy mechanisms, not evidence that a canonical record containing a variant preserves exact identity and payload. The native classifier and simulator must independently carry the validated nominal/variant field shape, preserving exact INT/empty semantics and rejecting incompatible payload access. Existing native domain/ordinal restrictions remain unless separately qualified.

Required evidence includes actual canonical record→variant construction/read/match, Some/None and wrong-variant access, detached/shared aliases, helper/call/tail transfer, forced-GC sole-owner lifetime, allocation failure diagnostics/recovery and native O0/O2 sanitizer runs. Baseline12 native executions do not satisfy these selected obligations. Publisher eligibility must combine complete VM proof with the independently qualified native intersection, never a syntax filter or coarse TAG_UNION whitelist.

## Budgets, phases and acceptance

No unconditional Analysis/Value/VmState/VmHeap/plan/view field, padding reuse, registry or cap increase is authorized. Analysis39840 and all six old profile byte/work/allocation results remain exact. Optional declaration/proof/runtime storage must have measured sizeof/capacities, checked arithmetic, charged copies/scans, retained live overlap and exact-cap/one-below refusal/recovery. Old map/array/INT/native bytes and no-union query schedules remain literal compatibility controls. The old simultaneous extension-count bound remains unchanged.

## Declaration-only API checkpoint (proposed, unimplemented)

The smallest first declaration owner deliberately describes exactly two complete layouts: one ordinary record with one union field and one nominal union with two alternatives, exactly one INT payload row and one empty alternative. Names are numeric string-table references, never a name allowlist. The record and union ordinal are each0; layout mapping is copied explicitly (union0, record1 for the proposed prior-only fixture). No maps, arrays, resource flags, reference modes, imported declarations, extra nominal instances or unrelated extensions are described by PREPARED in this first interface. This narrow declaration milestone is not an executable profile or a publisher decision.

Proposed internal header `ownership_union_fields_private.h`, implementation included from the existing ownership-contracts provider:

```c
typedef struct NvmUnionFieldDeclarations NvmUnionFieldDeclarations;
typedef enum { NVM_UFD_PREPARED, NVM_UFD_UNKNOWN, NVM_UFD_INVALID,
               NVM_UFD_LIMIT, NVM_UFD_MEMORY } NvmUnionFieldDeclarationStatus;
typedef struct {
    NvmUnionFieldDeclarationStatus status;
    const char *message;
    uint64_t bytes_reserved, work_reserved;
} NvmUnionFieldDeclarationResult;
NvmUnionFieldDeclarationResult nvm_union_field_declarations_prepare(
    const NvmModule *, NvmUnionFieldDeclarations **out);
void nvm_union_field_declarations_free(NvmUnionFieldDeclarations *);
bool nvm_union_field_declarations_layout(
    const NvmUnionFieldDeclarations *, uint32_t layout, NvmDeclarationLayout *out);
bool nvm_union_field_declarations_field(
    const NvmUnionFieldDeclarations *, uint32_t layout, uint16_t field,
    NvmV2LayoutField *out);
bool nvm_union_field_declarations_variant(
    const NvmUnionFieldDeclarations *, uint32_t union_ordinal, uint16_t variant,
    NvmUnionVariantFact *out);
bool nvm_union_field_declarations_nominal(
    const NvmUnionFieldDeclarations *, uint8_t tag, uint32_t ordinal,
    uint32_t *layout_out);
```

No borrowed row pointer or trusted execution bit is returned. Getters borrow the immutable owner for the duration of a call and copy numeric results; a copied result survives owner destruction but string indices refer to the source module's index namespace, not retained string bytes. They preserve output on invalid index/argument. All writable outputs must be disjoint from input module/owner/storage; genuine readable input allocation extents and exclusive stability are C API preconditions. No arbitrary-pointer validation claim is made. Each getter has a fixed four-logical-probe bound; future budgeted consumers precharge four before calling, including misses. There is no hidden mutable getter budget.

Preparation validates the whole supplied layout and ownership metadata for PREPARED, including every function result/local descriptor and the entire extension directory, not merely the selected union. It checks function/parameter correspondence using common readers, exact kinds/counts/names/referents/flags, v3 reserved bits, the single kind1 revision1 extension, all variant rows, contiguous payload coverage and trailing extents. Preflight must require the exact final layout cursor extent (the common decoder does not itself reject trailing bytes), exactly one extension of kind1/revision1, and exactly two variants before invoking shared readers. `ownership_validate_owned` may return OK while setting `projection.ambiguous`; preparation must explicitly reject that flag before PREPARED. All descriptor reference modes must be zero; exact signature/nominal references still validate. Missing/unsupported profile is UNKNOWN, which is no certificate of well-formedness. Observable malformed framing/correspondence is INVALID. LIMIT and MEMORY remain distinct. Executable instruction validation remains deliberately outside this descriptive query; no public verifier may return success because this owner exists.

The intended validation sequence is: bounded count/extent/profile preflight; exact positive reservation; detailed mixed-layout decode on the prior-only fixture; common `ownership_validate_owned` with NULL ordinary/map owner and a local projection, which enables existing complete-union grammar; a second bounded `union_facts_read` into the new owner's inline rows; final exact structural/profile checks; publish output last. Existing old projection constructor and its allocations/charge schedule are not called or altered. Any newly discovered common-reader incompatibility is a retained first failure, not permission to loosen grammar. A canonical byte fixture must independently pass the common validator before any PREPARED claim.

Proposed owner storage is `NvmV2Layouts layouts`, inline `NvmUnionVariantFact variants[2]`, two flag bytes, and four uint16 numeric indices (record layout, union layout, payload alternative, empty alternative). No Analysis/Value/VM/old-plan field changes. On current LP64 this predicts sizeof owner56, layout row16, field row12 and variant row12; these are predictions until measured. Two nonempty layout fields allocate separately: retained payload is sizeof(owner)+2*sizeof(layout)+2*sizeof(field), predicted112 bytes, four allocations total (owner, layout rows, two field rows). No zero-count allocation, strings, capacity growth or DFS allocation occurs on this prior-only two-layout shape. Temporary automatic storage is accounted separately: one local OwnershipProjection (predicted64 bytes on LP64), one NvmV2Layouts (16 bytes), two uint32 start slots (8 bytes) and two uint16 variant-count slots (4 bytes) if needed by the existing projection writer; cursors/scalars are fixed-size. Shared reader automatic arrays also remain fixed by existing compile-time ceilings, including extension path scratch; no source-count-sized VLA or recursion is introduced. Actual sizeof and compiler frame evidence must replace predictions before qualification. Decoder partial allocations are included in the same peak; the new owner never holds a duplicate decoded table. Use sizeof and checked sums in implementation, not hardcoded112. Independent allocator payload/peak and destructor-zero oracles must confirm the ledger.

Proposed new-only caps remain16MiB bytes and1,048,576 logical work, without changing old allowances. The schedule is explicit conservative pre-reservation, not machine instruction timing: charge64 before fixed header/argument processing; charge one logical unit before each byte visited by the bounded allocation-free preflight; after checked counts derive S=layout_size+ownership_size, D=sum(local_count+1), L=2 and V=2. Before decoder/common-reader/copy work reserve an additional `4*S + 32*D + 128*L + 64*V` with checked arithmetic. The four byte passes cover decoded framing, common ownership/extension parsing, complete variant copy and final cross-check; descriptor surcharge covers fixed mode0 correspondence and layout lookups, and row surcharges cover names/referents/two-variant comparisons. Preflight itself stops at the cap, so it cannot traverse arbitrary rejected bytes uncharged. Reject function_count>256 or local_count>256 before descriptor loops. The actual implementation review must map each loop to this schedule and retain an exact-limit/one-below test; the formula is a proposed policy, not already measured compatibility evidence.

All owner allocations remain private until full success. Failure frees every partial allocation and preserves prior *out, source bytes and prior owner; free(NULL) is valid. Diagnostic messages are fixed by status (copied declarations without execution authority / unsupported or unestablished declarations / inconsistent declaration bytes / declaration bound reached / declaration allocation failed), not inherited success text. Returned counters report charged work/bytes to the stopping point and are diagnostics only. A static positive-only reservation seam may qualify exact cap/overflow controls, but no exported bypass or caller-supplied validated view is proposed.

First tests: canonical union-first bytes and exact ordinal getters, source destruction, all descriptor/variant/reserved/trailing/count corruption (including unrelated later descriptors), unsupported shapes, allocation prefixes/prior-output/retry, immutable getter misses/output alias preconditions, independent retained-byte oracle, and exact new charge limits. Old declaration projection/array/map neighbors and six old allocation/work budgets remain byte-identical. No native, VM, transport or publisher enrollment belongs to this declaration-only patch.
