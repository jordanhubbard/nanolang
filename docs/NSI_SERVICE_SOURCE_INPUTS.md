# My File and TCP compiler inputs

I parse the exact catalog1 interface names `nsi:nanolang/filesystem` and
`nsi:nanolang/net` in both frontends. I retain the original counted strings,
source locations and relative companion paths. An accepted declaration does
not grant execution authority.

My C loader and Nano acquisition helper select the corresponding strict
binding validator before retaining a companion. A File declaration cannot
retain a TCP document, and a TCP declaration cannot retain a File document.
My snapshots record catalog1 File as identity1 and TCP as identity2; identity0
means no catalog. These are compiler-input selectors, not wire tags or grants.
The legacy snapshot API remains File-only. A repeated C import must match both
the retained path and catalog identity; I do not reopen changed input bytes.

I allow both catalogs in one bounded snapshot context. I retain each original
file, canonical interface and declaration until context destruction. The Nano
host module copies returned strings under its existing release ABI, so those
copies outlive the context. I reject an unknown selector before acquisition.
File/Socket binding plans remain distinct opaque types within the snapshot.

My catalog query API takes the same explicit identity and exposes immutable
type/method counts, names, domains and ownership facts. My old File query API
keeps its exact bytes. Nano independently renders each full catalog view from
the primitive queries. I retain File's previous view as a regression fixture;
TCP's view includes Conn, eleven SocketError fields and seven Endpoint fields.

I register exact artifact signatures in both self-hosted code generation and
native emission. The selected-open call has six parameters, including its
opaque context, catalog identity and counted paths. I preserve wrong-signature
and missing-artifact refusal. I give the catalog module's internal descriptor
symbols private names so the C native driver can link it with the input module.

I have not added TCP namespace/type resolution, ownership lowering, wire
metadata, service dispatch or selected network shadows in this layer. Those
remain required before Socket source execution. My File namespace validator
continues to reject a TCP declaration at the later admission boundary.
