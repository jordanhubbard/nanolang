# I replace scalar tail frames without growing the host stack

I track `task_c1786e6f33d64420b3688c2c8cad6b3b`. My unchanged qualified byte-call fixture reaches a verified TAIL_CALL that my scalar LLVM/Wasm profile currently refuses. I do not implement this by ordinary recursion or an optional LLVM tail hint.

Before source changes I specify a private trampoline for modules containing TAIL_CALL and admitted by my scalar/literal-string profile. Functions without that module requirement retain their existing ABI. The trampoline repeatedly calls a compiled function body, receives either a completed scalar result or a next-function request, and loops after that body has returned. Each ordinary CALL starts its own trampoline invocation; each TAIL_CALL returns its next target to the existing invocation. Host frame depth therefore follows ordinary CALL nesting, not the number of tail edges. I still compile instruction bodies to LLVM blocks rather than dispatching opcodes.

A body receives its declared tagged arguments plus a pointer to the invocation's bounded argument buffer. Before a tail transfer it pops all arguments into SSA values, then writes the complete next argument tuple to that buffer and returns the target index. The buffer is sized from the maximum verified arity in this module. The old body's operand stack and locals end with its return. The trampoline loads all arguments before entering the next body; no pointer into a returned body's storage escapes. Actual parameter tags and result tags retain their checks. The existing verifier requires identical caller/callee tail result signatures and valid indices/operand depth.

The completed/next result is a private aggregate carrying a tagged value and a target discriminator. Void completion carries a neutral value which ordinary void calls discard. Entry and global initialization use the same trampoline only when required; globals and initialization order are unchanged. Ordinary modules retain existing textual output and call handling.

I initially admit this path only for scalar and literal-string modules, whose values have no owned heap roots. Managed strings/arrays/records continue to refuse TAIL_CALL until a separate reviewed ownership transfer and first-error cleanup contract exists. I do not broaden their shared opcode whitelist accidentally. Raw general verification and VM behavior remain unchanged.

Acceptance includes self and mutual tail calls with different arities, argument swaps, locals, globals, initializer tails, zero-result functions, byte/enum/bool/float and static-string carriers, ordinary calls around tail chains, deep bounded-stack execution, malformed signature refusal before publication, and unchanged existing LLVM/Wasm suites. I qualify the same modules on VM, generated C, LLVM interpreted/optimized/native and Wasm engines as available in the required matrix. I retain the original qualified byte-source failure until its complete producer/backend control passes. This child does not complete managed tail calls or the full 5.1 roadmap.
