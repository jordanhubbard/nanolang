# My bounded shadow timing diagnostic

I retain the original Darwin `4205973e0` bootstrap timeout and one copied-
provider verbose diagnostic. Buffered progress cannot establish which shadow
was active at the deadline. I add diagnostics only when
`NANO_SHADOW_TIMING=1`; other values leave the existing route unchanged.

I emit numeric source index, top-level AST item index and selected ordinal at
each interpreted shadow start/end. Source indices use the existing ordered
import list followed by the root; item indices refer to the actual selected
program. I emit no token, function-name, path, environment or credential text.
The retained source inventory and parser selection identify these sites.
Fixed phase labels distinguish callback preparation, interpreter selection,
module initialization and individual shadows.

Each record contains raw monotonic seconds/nanoseconds and process user/system
CPU seconds/microseconds, with explicit syscall-validity flags. Parent records
cumulative reaped-child usage before fork and after terminal wait using POSIX
`getrusage(RUSAGE_CHILDREN)`. Their difference includes any children reaped in
that interval; I do not call it a per-PID measurement. I preserve `waitpid`,
status interpretation, the completion pipe and both ten-second clocks.

I use one bounded stack buffer and direct stderr writes, with bounded interrupted
write retries. Each process/translation unit admits at most 4096 records, including an
explicit final truncation marker; output failure disables subsequent records.
No heap allocation or new file is needed. Diagnostic I/O and clock calls add
work under the original deadline; a diagnostic result is not uninstrumented
acceptance. The external runner retains stderr durably. I do not change existing
stdio buffering or use a diagnostic failure as successful shadow completion.

This is an unexecuted source checkpoint. I require source review before any
instrumented build or program invocation, and retain original failure trees.

I preserve errno around every diagnostic call and cache the opt-in independently
in each translation unit. The header joins my existing compiler prerequisites
and explicit installed SDK input inventory; generated inventory bytes are
regenerated by the canonical script. No public ABI or token schema changes.
