I will distinguish compiler-created checker placeholders explicitly. I add a `checker_builtin_placeholder` bit to the C `Function` descriptor. Ordinary `env_define_function` publication always clears this bit, so copying a marked descriptor into another environment or importing an alias does not grant placeholder authority. Only `register_builtin_functions` marks the exact rows it just appended, after its synchronous registration completes. The registry's separate static cache stays unchanged; this bit does not grant intrinsic dispatch identity.

I audited the C function-table writers. `env_define_function` appends descriptors and invalidates the index. The REPL hot-patch assignment bypasses that append API, so it must explicitly clear the bit on replacement. Module metadata extraction copies descriptors and must clear the bit on the independent snapshot. Generated metadata descriptors are zero-initialized and published through ordinary registration. Other source, alias, generated-list and module consumers use `env_define_function`; they cannot copy the privilege. The bit owns no allocation and requires no destructor. This changes the C descriptor layout and requires fresh dependent providers before execution.
