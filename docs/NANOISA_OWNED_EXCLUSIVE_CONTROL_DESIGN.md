## I admit one family with two checked loop forms

I retain entry0 with no parameters and INT result; helper1 has exactly one mode2 reference to a scalar INT/BOOL leaf and INT/BOOL result. V1 local calls may observe/mutate different exact live caller slots sequentially, as the returns anchor requires. V2 path calls use one exact live root slot/layout, nonempty validated paths of length<=2, root depth<=3, and the original exact nominal endpoint. Both use REGION_BEGIN, BORROW_LOCAL_EXCLUSIVE or BORROW_PATH_EXCLUSIVE, CALL_REF, REGION_END with exact operands and complete instruction coverage. I do not add multiple simultaneous references, path copies, overlap, escape, mixed consuming graphs or additional functions.

The helper grammar consists of exact scalar declarations/stores, total comparisons/Boolean/casts, exact parameter REF_GET/REF_SET, existing wrapping ADD, structured diamonds and scalar returns. No helper calls, ASSERT, foreign operations, owner construction/destruction, DIV/REM or new arithmetic is admitted. A continuing join intersects initialized locals; returned arms cannot contaminate continuing state. Borrowed parameters are never counted as owned-live values to consume. Every normal helper path has an exact scalar return; no unreachable instructions are silently dropped to satisfy this rule.

Each helper loop must independently satisfy one of these forms:

1. Every reachable body arm returns from the helper. A false pretest executes zero bodies; a true pretest executes one body and returns. The syntactic backedge may be unreachable only where the original verifier admits it, and complete instruction coverage must still account for it.
2. An exact scalar local has a dominating known integer initialization A; the pretest is that local<B for literal B, with A<=B. Every continuing backedge path performs exactly one rank update rank+1; all other writes to that local are rejected. The update is the existing exact wrapping ADD operation, but its rank proof independently proves no wrap: each executed update starts below B<=INT64_MAX and reaches at most B. Early-return paths need not increment because they do not reach a backedge. Conditional joins must agree on the once-only update count for every continuing path. A missing, doubled, conditional-only, aliasing or hidden rank write fails proof. Unknown initialization or another comparison/update form refuses this initial profile.

I initially exclude nested helper loops and break/continue jumps outside the existing structured region grammar. Caller nested loops and returns retain their existing semantics. This is a bounded family implementation, not a general termination checker or a claim that every originally accepted helper loop is total.

## I distinguish termination from bounded shadow work

The checker computes a conservative logical-work bound from the validated helper region tree. Each scalar statement and expression node costs at least one; branch cost includes its condition and the maximum reachable arm, and sequential costs add. Fixed guarded ADD expansion receives its explicit maximum branch/statement cost rather than zero or an assumed unit loop. A return-only loop costs both the final test and its maximum one-body path. A rank loop uses the proven trip count B-A, including every reevaluated condition and the final false condition; return paths may only reduce this bound. Arithmetic for bounds uses unbounded host integers and rejects overflow/unknown costs, never guest arithmetic.

I propose a new conservative proof-work admission cap of4096 logical operations per helper invocation, independent of the existing4096 encoded-instruction bound. This new cap only refuses additional unproved/expensive reconstructions; it changes no source, verifier or runtime budget. Each generated consistency shadow invokes the helper exactly twice, so its computed bound is at most8192 plus the explicitly counted finite construction/destruction/assertion work. The unchanged128 local and two-function preflight limits apply separately. These are structural logical-work bounds, not wall-clock guarantees.

Only after this proof may a new exclusive-control shadow construct two independent zero/false leaf owners (v1) or complete root trees (v2), invoke the helper directly on the exact chosen endpoint, consume both owners completely and compare final scalar results/fields. Exclusive mutation means final fields are compared between the two runs; they are not incorrectly asserted unchanged. This is consistency evidence only, not branch coverage or original-shadow recovery. The real anchors remain the mutation/result oracle. The literal first-call witnesses in the returns source are additional concrete evidence; they do not permit arbitrary nonterminating helpers. Existing ASSERT-bearing profiles keep their stricter literal-witness rules untouched. No helper interpreter, hidden runtime dispatcher or proof counter is emitted.
