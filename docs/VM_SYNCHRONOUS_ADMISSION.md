## My first bounded implementation proposal

I propose a private C-stack certificate for an ordinary, standalone execution segment inside one `vm_call_function_impl` invocation. It is not an owned proof, a general verifier proof, a new public API, a module field, or a raw-pointer trust cache. I derive it only after the unchanged complete core admission path succeeds with `required == false` and no matched owned/mixed proof. I retain its fact only while execution remains within a region that cannot hand control to embedding code or write caller-supplied linear memory. The first core entry of every public invocation remains fresh. All current public verification, service precedence, owner ARRAY admission, reference readiness, frame checks, dispatch bounds, and cleanup remain in force.

My private representation is a small automatic `VmOrdinaryAdmission` containing the admitted `VmState *`, root `NvmModule *`, and a valid bit; it allocates nothing. The pointers identify the region already checked; pointer equality alone can never create the certificate. Its only creator is the completed existing core admission sequence. Its only consumer is the subsequent synchronous core call from that same private loop. Public `vm_core_execute` supplies no certificate and never exports one. Existing `VmOwnedInvocationProof`, its matcher and its lifetime remain separate and unchanged. In particular an ordinary certificate must not make `admitted` or `owned_execution` true.

I propose extending only the private core signature to accept this nullable certificate. Reuse requires its valid bit, exact VM/root/current-module identity, current module equal to root, zero linked modules, no callback runtime, and no opcode tracing. Otherwise I clear it and perform the original admission in its existing order. A successful fresh admission may arm it only under these same restrictions and ordinary classification. I do not memoize allocation failures, refusals, or owned/mixed results. Failure/status ordering remains the existing path. Linked programs remain entirely on their original path.
