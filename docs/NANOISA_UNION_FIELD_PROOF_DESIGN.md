## Conservative variant safety

Each AGG_PACK/AGG_VARIANT allocation site has a fixed union ordinal and variant operand. A new distinct origin kind shares the existing64-origin namespace; static origin identity is an allocation site, not a runtime pointer. A sidecar records that origin's exact variant and historical payload Value. The unchanged accepted anchor constructs only its payload-bearing variant, so the record-field history contains only safe payload origins. AGG_GET0 is admitted only if every reaching origin has the exact nominal union and payload-bearing variant with proved INT payload. Unknown, empty-origin, mixed-kind or mixed payload/empty receiver refuses.

AGG_TAG consumes a proved union and produces ordinary INT. The first slice introduces no tag-test relation and does not reuse Value.relation/relation_tag, which already carry global TYPE_CHECK provenance. DUP/tag/EQ/branch therefore cannot narrow a mixed origin set. An exhaustive source match over None may conservatively refuse because the syntactically visited Some arm reads payload, even if that arm is dynamically unreachable. Bare None construction, tag inspection and empty teardown require independent positive controls; these are not general exhaustive-match parity. `.match_coverage` is advisory only. A later exact relation proof requires separate design and a demonstrated accepted-source gap.

Union-payload AGG_SET remains refused. Outer.boxed replacement, if included, merges the replacement's union origins into the record field's monotone historical Value; prior/detached variants remain in the history. Constructed INT payload writes accumulate per allocation site over loop iterations and calls. A currently safe payload cannot erase a historical incompatible write. Seeded parameters, results, calls, tails and globals retain unknown/origin bits and the existing fixed-point/returned-summary rules. No signature/tag whitelist may launder an unproven union.

## Proposed owned staging and call chain

New module-taking structure preparation owns both the new declaration owner and decoded-function staging. To preserve Analysis/Value layouts and their established allocation helpers, a separately typed union structure wrapper may own an unchanged NvmRecordArrayStructure carrier for decoded functions/stacks with `carrier->declarations == NULL`, plus the exact NvmUnionFieldDeclarations owner. This is constructor-established storage, not a forged executable token: only the new internal module-taking constructor creates it, old structure entrypoints are unchanged, and no public call accepts a caller-supplied wrapper. Its decoded functions must pass all original header/service/callback/closed-module, signature/stack/decode checks and the exact new opcode/operand checks before being transferred to analysis.

The new analyze entry passes an explicit optional union context through discovery, constructor/field transfer, call/global seed/join, final constraints and publication. Old wrappers pass NULL. It selects a distinct record-layout-copy routine using charged new declaration getters; it never calls the old ra_prepare_records on a carrier with NULL declarations. The old common allocator/budget machinery may continue using the genuinely owned decoded carrier. The new output publication path likewise never invokes ra_publish, whose old declaration transfer expects an old projection owner.

Proposed mutable context payload: one owned declaration pointer, `Value payloads[64]`, `uint8_t variant[64]`. With the existing16-byte Value and pointer8 this predicts1096 bytes, to be measured and charged only on the opt-in route. Union kind/record field origins remain in the existing arrays; variant entries are interpreted only for the distinct new union origin kind. The structure wrapper is two owning pointers (predicted16 bytes). Transfer declaration ownership once from wrapper to context, clear the source pointer, and later transfer once into the frozen report only on complete success. Every failure frees decoded storage, context, declarations and pending report while preserving output.

Suggested internal module API:

```c
typedef struct NvmUnionFieldProof NvmUnionFieldProof;
NvmArrayEligibilityResult nvm_union_field_proof_prepare(
    const NvmModule *, NvmUnionFieldProof **out);
void nvm_union_field_proof_free(NvmUnionFieldProof *);
```

The report is descriptive immutable proof output, not an execution API. Getters must copy exact origin kind/nominal/layout/variant, historical record field origins and payload tags/unknown, plus prepared function stack facts. No mutable Value pointer, Analysis pointer or caller-supplied trusted plan crosses into runtime. Concrete frozen row declarations, owning allocation capacities and getter charge constants must be reviewed before implementation; they are not fixed by the mutable context proposal above.

## Frozen facts, copied getters and concrete overlap proposal

Proposed new `NvmUnionOriginFact` has four uint32 fields (`function`, `pc`, `nominal_ordinal`, `layout_index`), uint8 `kind` and `variant`, uint16 `member_count`, and one `NvmRecordValueOrigins member`. Predicted LP64 size40: a record row has its one historical union-field summary; a payload variant row has its one historical INT summary; an empty variant has member_count0 and all-zero member. A record uses an explicit not-a-variant sentinel outside0/1. Nominal and layout remain distinct even when one numerical value happens to match. All unknown flags must be zero in a successful report; origin masks and tag masks must agree with independently enumerated frozen kinds. Flow-only relation fields are not copied.

`NvmUnionFieldProof` owns five pointers: declarations, origin rows, global rows, function-result rows, uint16 stack rows. Its inline counts contain uint32 origins/globals/functions and uint64 bytes_reserved/work_reserved. Predicted owner72 bytes; exact implementation uses sizeof and a measured oracle. Allocate rows at exact nonzero counts (O<=64,G<=256,F<=256), no malloc(0) or minimum-one allocation; F is positive for an eligible module. The old analysis record plan is temporary and is not transferred into this owner. Actual retained allocation formula is `sizeof(owner) +112 + O*sizeof(origin_row) +(G+F)*sizeof(NvmRecordValueOrigins) + F*sizeof(uint16_t)` on the measured declaration ABI, predicted `184+40O+16G+18F`. Portable code obtains declaration retained cost from its actual constructor/sizeof contract rather than hardcoding112.

```c
typedef struct { uint32_t origins, globals, functions;
                 uint64_t bytes_reserved, work_reserved; } NvmUnionProofCounts;
bool nvm_union_field_proof_counts(const NvmUnionFieldProof *, NvmUnionProofCounts *);
bool nvm_union_field_proof_origin(const NvmUnionFieldProof *, uint32_t, NvmUnionOriginFact *);
bool nvm_union_field_proof_global(const NvmUnionFieldProof *, uint32_t, NvmRecordValueOrigins *);
bool nvm_union_field_proof_result(const NvmUnionFieldProof *, uint32_t, NvmRecordValueOrigins *);
bool nvm_union_field_proof_stack(const NvmUnionFieldProof *, uint32_t, uint16_t *);
```

Each is a four-logical-probe immutable copy query including a miss; callers precharge when budgeted. Declaration layout/field/variant/nominal getters are exposed only as typed forwarding copy functions with the same four-probe bound. No carrier, declaration-plan or mutable row pointer getter exists. Output/writable-work storage must be disjoint from the owner and its owned storage; failure preserves outputs. Copied numeric results survive owner destruction, but string indices still name the source namespace. Free releases all four dynamic row arrays and declarations exactly once; partial freeze is private until every row validates.

The carrier is a private implementation detail. The typed union wrapper constructor/destructor and analysis handoff remain in owning TUs; no header getter returns NvmRecordArrayStructure*. The old carrier's NULL declaration member is an explicit invariant of only this new constructor. New copy/freeze dispatch is selected by a non-NULL independently constructed union context; old declaration copy/publication functions are not called on that branch. Context and map outputs are mutually exclusive. Failure after decoded transfer clears the source decoded entries and leaves one owner per allocation, following the existing decoder transfer rule.

Before calling the declaration constructor, the new proof budget conservatively reserves its unchanged16MiB byte and1,048,576-work ceilings once. Its returned actual112/1152 figures are diagnostics, not added again or refunded. This simplifies preallocation safety at the cost of a conservative new-profile allowance; fit remains to be measured on all actual inputs. Existing structure scratch, decoded-capacity/reallocation overlap and Analysis reservation then use the same proof cap. New wrapper, full context sizeof (including `64*sizeof(Value)`), copied analysis record layout/maps/fields, all function states and queues, global-flow storage and final frozen rows are charged before allocation; no overlap is subtracted while analysis/context remain live. The terminal freeze ledger adds `sizeof(owner)+O*sizeof(row)+(G+F)*sizeof(value)+F*sizeof(stack)` on top of retained declarations and the still-live analysis/context. Source declarations transfer without another copy. No current old-profile allocation/step is changed.

All new scans charge before the loop: one origin fact inspection per origin, four probes per declaration getter, one member/tag-mask validation per row plus one per checked origin-bit edge, and one copy step per frozen row. Existing analysis_alloc initialization charges remain in addition. Whole-function result/global final checks and freeze charge O+G+F and their actual edge traversals; there is no uncharged repeated declaration search. Future recipe/image constructors must reserve the frozen proof's actual retained capacities during snapshot/reproof, independently from their own new allowances; no claim of a shared existing budget across stages.

## Fixed-point completeness and first proof corpus

Bottom (not-yet-populated) field/callee facts during iteration are distinct from explicit unknown provenance and from a known empty variant. A transfer with insufficient forward facts may defer its successors, adding no invented tag/origin and no successful result. Existing monotone changes reschedule the function until convergence; no Value relation field is borrowed for a pending bit. After convergence a charged scan of every reachable stored instruction obligation must reject every still-deferred/unknown union receiver or payload. The blocked instruction itself remains reachable even when no successor or RET received a propagated state. Missing propagated states never establish CFG unreachability. A mandatory negative has an unresolved callee result blocking before the first union use/return; it must not disappear from final completeness checking. A definite empty/mixed receiver at payload access refuses under the conservative policy. Previously propagated optimistic facts cannot hide a later historical conflict because final checking reexamines full monotone origin/write summaries.

The implementation must demonstrate this scheduling with forward ordinary CALL and acyclic TAIL helpers returning a Some union, a returned union placed into Outer, historical return/global aliases, and an unresolved-return/global negative. UNION helper signatures require exact copied nominal descriptors and the new structure/type checks; they are not admitted by coarse TAG_UNION alone. Existing callgraph/function/stack/SCC rules remain unchanged. None construction/tag and empty lifetime are positive obligations, but None exhaustive-match payload-arm acceptance remains a documented follow-on gap. If the existing worklist cannot represent the proposed deferred successor behavior without new persistent storage, stop for interface review rather than adding an uncharged table or poisoning bottom with an irreversible unknown tag.

The approved owning-TU private header contains the two-pointer typed wrapper directly; no carrier getter or caller-supplied execution capability exists. I transfer the carrier once into Analysis, clear the wrapper carrier pointer, then move declarations into the opt-in context and clear that source pointer. Failure destroys the remaining wrapper children, context declarations and Analysis carrier exactly once. This is source design until compiled and measured; the16-byte wrapper remains a prediction.

The first actual baseline corrects my transport expectation: unchanged public generic v2 conversion already roundtrips these complete union declarations (44 layout bytes and84 ownership bytes), while both original and reconstructed modules fail public verifier/native selection. Conversion is descriptive, not admission; the existing converter documents max_stack0 for verifier-rejected functions. My proof gate preserves exact converted metadata and independently requires public verification/native refusal, rather than imposing a new converter refusal. The initial overly strong test and unchanged-provider reproduction are retained.

Actual seed and Nano match code includes PUSH_BOOL0/ASSERT/HALT. I model HALT only on this union proof route as terminal without propagating successors or publishing function result/global-return facts. A function with another normal RET may have a successful returned summary; a HALT-only callee cannot unblock a caller. Direct value/void HALT-only callee negatives and a branch with RET versus HALT establish this distinction. VM trap_halt/native nfx_halted behavior motivates the proof terminal; no future runtime recipe or supervisor behavior is qualified here.

The historical-field precision boundary is explicit: a union alias loaded through a record field before replacement still receives that field's complete fixed-point Some/None summary, so later payload access conservatively refuses. This is not proof that the source/runtime program is invalid. A Some retained directly before record construction preserves its exact allocation-site origin and remains a positive detached-alias control after replacement. I do not introduce temporal snapshots in this slice; field-read alias precision remains a follow-on alongside exhaustive None-match precision.
