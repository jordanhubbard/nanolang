# I retain exact byte field contexts

I repair ordinary record constructors and explicit spread overrides whose resolved checked field declaration is exactly `u8`. Literals 0 through 255 produce exact U8; out-of-range numeric literals refuse before output publication. Existing U8 values preserve their tag. Checked computed INT values evaluate once and convert modulo 256 through my existing CAST_U8 or defined native uint8_t conversion. I leave raw expression types intact and reject other definite types or unresolved field identity. This extends the already approved #1004 contextual policy to the missing field boundary; it does not change global type compatibility or solver/verifier authority.

For a direct constructor containing U8 fields I validate field names and duplicates before emitting values, stage every supplied operand in written order once, then arrange stored values in declaration order. A spread evaluates its base once before explicit overrides in written order. Each U8 override receives its checked conversion, inherited fields remain unchanged, and allocation/error cleanup follows existing staging helpers. I do not infer conversion authority from advisory metadata or matching field spellings alone.

I require both C and Nano checkers and bytecode emitters, legacy native C direct/spread lowering, and strict C's pure numeric direct field boundary. Strict C's existing spread refusal remains a separate profile boundary. I do not claim ordered strict C constructors: its direct compound initializer lacks guaranteed C evaluation order, and general record temporary lifting needs a separate checked-identity change. The original strict ordering fixture also meets an existing unsupported cast_int call refusal; I retain that failure separately from byte conversion. I retain exact tags/layouts, 0/255 literals, computed 256/-1/signed boundaries, U8 identity, reverse-order side effects and once-only evaluation. Wrong types, literal ranges, duplicate/unknown fields, unknown/cyclic/resource cases preserve refusals and prior outputs. Full fresh-stage/platform qualification remains aggregate work; no isolated full bootstrap is part of this slice.
