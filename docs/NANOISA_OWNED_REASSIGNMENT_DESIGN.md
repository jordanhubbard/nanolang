## I bound lifetime and authority

My first slice is the existing two-function borrowed single-exclusive entry profile (v1 local or v2 exact path), with its existing scalar leaf, complete reference regions, descriptor depth and helper grammar. Only entry ownership stores gain reassignment; helper-local owners, new signatures and consuming-call graph extensions remain separate. Original verification precedes facts and both outputs.

A bytecode local slot and retained nominal layout identify the destination. A source name is diagnostic only; two lexical bindings with the same spelling remain different slots. A lifetime generation is the current owned value occupying that slot, not a new name or a fresh copy. OWN_MOVE removes that live value and leaves the source dead; the popped exact owned operand is consumed once by OWN_STORE, creating the destination's next live lifetime. OWN_UNPACK consumes its generation and yields exact field values. A repeated store is admitted only while the destination is dead, with exact declared type/layout and no open reference region. No old reference or owner-stack operand may remain usable as an alias to the consumed generation. Complete region parsing and the original affine verifier remain mandatory; reassignment cannot revive a borrow slot or accept stale reference reads.

The first declaration must dominate every repeated assignment within its emitted lexical scope. I retain a distinction between a syntactically single declaration executed on each loop iteration and a second syntactic store into an existing declaration. Branch-local declarations never escape to manufacture an outer owner. A destination declared on only one arm cannot justify assignment after the join. I intersect scalar initialization and declaration availability across continuing arms, ignore terminal arms for continuation, and require the existing exact live-slot/nominal agreement. For this first slice I do not add a live owner whose origin differs across continuing branch arms: path-local reassignments must finish consumed, or restore the same incoming owned value.

A zero-iteration loop retains the exact incoming owner and declaration state. A continuing loop backedge must restore the same incoming owned value to its exact slot/layout after temporary moves, with no additional live body-local owner. The assigned replacement in the anchor is installed before the loop, so it becomes that loop's incoming owner. I do not infer that merely matching layouts permits an arbitrary replacement owner at a backedge. Ownership-origin reasoning uses transferred exact operands/region state, never names or guessed equality of fields. A loop-body-only declaration still has one syntactic declaration and a new runtime lifetime on each iteration; the old used-set union must not misclassify that existing supported behavior.

## I make the origin-state interface explicit

The current `live` map carries layout numbers only; that is insufficient for the new restoration proof. For this new reassignment analysis I retain a parallel immutable origin state, separate from layout/type checks and the syntactic declaration-availability set. A pack creates an `OwnerOrigin(function, instruction, children)` token. Children hold the exact ordered owned-child origins consumed by that pack; scalar fields carry no owner origin. Distinct pack instructions remain distinct even when layouts and scalar values match. Loop-body pack sites denote body-local lifetime instances, never the incoming token at a loop header. No runtime generation counter or generated interpreter is introduced.

The analysis associates each owned expression/operand with its origin and each live owned slot with that same origin. `OWN_MOVE_LOCAL` removes the slot entry and attaches its origin to the existing single stack result. `OWN_STORE_LOCAL` consumes that operand once and installs its origin into the dead destination; it does not manufacture a new object identity. The destination binding lifetime changes while the owned object's identity transfers. `OWN_UNPACK_LOCAL` consumes the parent's origin and gives every owned child result its corresponding retained child origin. Moving a parent therefore preserves every nested child's identity. Scalar extraction carries no owner token. Original verification, exact types and the existing linear owner-stack discipline remain prerequisites rather than being replaced by this side state.

`region` receives and returns origin maps alongside its current initialized/live/used state. It clones the map for each arm and compares exact origins for every live slot on continuing joins; terminal-arm origins do not contribute. A loop analyzes a symbolic incoming map, then requires every continuing backedge to restore that exact map and rejects additional live body-local tokens. Its exit retains the incoming map for zero iterations. The new proof does not equate equal layouts or same-spelled names with equal origins. Complete reference operations temporarily refer to the captured live root origin and exact projection; their region ends before a subsequent transfer, and no reference-origin entry survives that end.

Declaration availability is another state: first-store slot, lexical declaration region and dominance, not an ownership token. A previously declared but dead slot can be assigned only when that declaration remains available in the current lexical scope. A live origin does not itself authorize a declaration, and a remembered declaration cannot resurrect an old origin. The explicit `own_assign` node records a proven transfer to an available dead binding; renderers consume this proof without deriving authority from names. Ordinary modules without reassignment retain their old IR and bytes. Defensive origin-state tests cover wrong-child restoration, same-layout fresh replacements, swapped incoming owners and a stale operand/reference from a prior destination lifetime.

## I separate declaration from assignment

The region tree gains an explicit owner-assignment node after the transfer proof; existing own_store stays the first declaration. C emits typed first initialization and later assignment, and Nano emits a mutable first owner binding plus `set` for repeated assignment. No default/uninitialized resource is manufactured, no heap ownership policy changes, and no stale C temporary is read after its logical move. Only actually reassigned slots gain mutable declarations in profiles where they were not already mutable. Functions without reassignment must retain exact previous output bytes.

I retain explicit source-order operand materialization and once-only moves. A statement does not turn a consumed temporary into an implicit copy. Existing shadow constructors create their independent owners and consume them as before; this slice does not replay caller lifetime assignments in the generated consistency shadow or claim original-shadow coverage. Selected original source shadows remain independent producer evidence. The existing bounded helper-work proof is unchanged.

Local accounting follows the emitted tree: a repeated owner assignment introduces no declaration local, while its moved source temporary still counts. First declarations, pack/unpack staging and all existing branch/loop costs remain counted. I measure ordinary regenerated entry/helper/selected-shadow locals for both unchanged derived anchors first. If either unchanged anchor exceeds128 or another existing output profile gate, I retain its ordinary atomic refusal and return for review; no assertions are removed and no budget is raised.
