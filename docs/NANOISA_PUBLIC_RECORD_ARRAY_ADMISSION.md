# My proposed public flat-array record admission

## My existing proof and missing connection

I already have a private declaration projection, original-module structural check, finite record/array origin analysis, copied execution plan, and private counted VM qualification. `NANO_RECORD_ARRAY_PRIVATE_RUNTIME` excludes the last interface from ordinary builds. My public ownership validator rejects ARRAY_FIELDS, my v2 bridge delegates to that validator outside existing specialized routes, and my ordinary publishers omit array fields. I cannot remove only a publisher guard: doing so would make previously accepted source fail publication or execution.

The ordinary VM and C translator already execute array-bearing records without retained array-field authority. I propose to qualify their existing execution against a freshly checked flat-array declaration and flow proof. The private counted VM is a comparison provider; its existence does not certify either public consumer.

## My bounded first route

I propose a distinct, synchronously prepared admission query using the existing complete private structural/origin preparation on the original immutable module. No caller supplies a trusted bit, borrowed proof, replacement declaration table or reusable module-address token. Every public invocation recomputes admission before using unchecked execution facts. The selected corpus excludes host callbacks, foreign/service/passive contracts, captured/indirect calls, resource/reference transfers, linked modules, nested array elements, record array elements and executed unions. Existing private limits remain unchanged.

I require all function bodies, including unused helpers, to have supported exact flow. Ordinary record DAG fields may contain exact scalar/string/record values and flat arrays of INT/U8/FLOAT/BOOL/STRING, with one exact element contract on every array origin through every alias and mutation. Ambiguous arguments, incomplete ownership declarations, conflicting field elements and exhausted limits refuse. I preserve original code, strings, layout order, per-kind ordinals and all metadata bytes.

I do not make `nvm_ownership_contracts_validate` generally accept ARRAY_FIELDS. The ordinary public verifier, standalone VM admission, C translation and v2 bridge need explicit matched routing. LLVM/Wasm and other selectors retain their prior decisions. Service and existing owned-array/mixed routes retain priority; malformed or overlapping metadata cannot fall through to a less restrictive route. General linked and function-only verification must either recompute the complete admissible original module or retain refusal; they cannot treat a single function as proof of a heap graph.

The private preparation path currently uses original range/contract checks and its own declaration projection rather than recursively calling the public verifier. I must preserve that acyclic dependency when adding public wrappers. The v2 bridge needs exact copied stack bounds with the existing report's function ceiling, checked allocation and size arithmetic; I must not reuse the unrelated eight-function specialized buffers.

## My source and publication boundary

Only after matched consumers pass do I extend both ordinary publishers with exact element bindings. I derive them from checked full annotations and canonical declaration identity, retaining actual runtime ordinals. I stage optional metadata and ask the same admission query before attaching it. An otherwise valid source program outside this bounded profile keeps its previous metadata omission and source behavior; it does not acquire fabricated complete authority. Malformed emitted metadata is an implementation error, not permission to discard a failed proof silently.

I compare C seed and both freshly built selfhosted generations, including imported noncolliding and same-spelled declarations only where the existing canonical identity proof applies. Generic and unsupported nominal fields remain UNKNOWN in this first route. This checkpoint cannot close #1001 by itself.
