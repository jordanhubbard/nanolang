# I crossvalidate a private SDK description generation

I implement the bounded description slice of `SDK_PROVIDER_CROSSVALIDATION_PRECODE.md`. `nvm_sdk_description_prepare` takes an existing V2 module, revision2 provider/lifetime bytes, a shared preparation budget and an unpublished output slot. I own an independent complete module snapshot, the shared typed declaration plan and an owned wire transport. Every refusal preserves the old output and both budget fields. No runtime module, cache, active borrow or loader is changed.

I check exact STRING names, owner/name/kind/ordered generic keys, nominal ordinal uniqueness, signature coarse counts/tags and original subject selectors. A field's complete ARRAY type must agree structurally with its retained ARRAY_FIELDS element, while FUNCTION/OPAQUE fields require explicit bindings. This new private complete profile requires one exact binding for every function and import, including scalar subjects; existing entry points retain their old rules. Every unused row is checked too.

I remove only explicit ARRAY/FUNCTION/OPAQUE reference edges before checking the entire type/key graph for cycles. Named layouts also link to their nominal keys, including when reached through anonymous tuple fields. By-value storage and generic-key cycles have no visited-pair exemption. Complete equality uses a charged bounded pair worklist only after this graph check. The lifetime graph independently removes only ARRAY/FUNCTION edges before its cycle check.

I validate every policy in its own call context, including policies unused by imports. Parameter/result direction and owner-argument bounds propagate through nested fields; callback signatures introduce their own argument count and reverse the transfer direction. Actual import roots must match their selected exact signature and call policy. Existing top-level callback rows must agree on import, parameter, original signature selector, shared V1 ABI and execution mode. I do not admit an undefined aggregate callback ABI. Container and nested independent drop hooks cannot both claim the same storage without a future exact ownership proof. An independent charged all-node traversal carries `(node, ancestor-drop-present)` state across every edge, including hookless intermediate nodes and unused components; argument/result context deduplication cannot erase that ownership state.

My private reader checks provider requirement strings and actual import symbol strings as data only. It does not equate an artifact path with a logical module name. Generation manifests, target/ABI compatibility, artifact/generation digest verification, symbol-to-generated-adapter mapping and same-image hook provenance remain unresolved until the separately required attachment stage. No API in this checkpoint loads an image or creates an executable descriptor. A shallow const module view is contractually read-only, including nested C pointers.

The only consumer is the owning declaration fixture, which includes this source privately alongside the already qualified snapshots and codec. No Make/runtime consumer or feature bit is activated. The original legacy, direct-V2 and typed fixtures remain. Additive controls cover owner aliases versus same-basename declarations, enum/opaque identity, exact selectors, missing/duplicate fields, unguarded generic cycles versus explicit ARRAY references, independent output, exact/minus-one budgets, allocation-prefix rollback/recovery and unused policy call contexts. Strict ordinary and allocation-instrumented C syntax checks precede source review; execution is still held for that review.

Generated C aggregate adapters, complete provider attachment, typed callbacks, COP graph envelopes and full installed source-hidden/read-only SDK acceptance remain required work. This private description slice is not their completion.
