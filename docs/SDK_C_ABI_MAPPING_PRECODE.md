# I bind semantic declarations to explicit foreign C storage

I refine the generated-image contract after auditing the actual producer. `ModuleBuildMetadata` has headers, sources, owned string returns and retained callback adapters, but no general foreign record/union/tuple C mapping. `emit_native_type_info` describes my existing source-native carriers: it deliberately uses `void *` for opaque values and generated tuple/callable names. Foreign extern record/union/enum definitions come from their declared C headers. The compiler-schema exclusion catalog owns only its registered runtime records. None of these facts permits guessing an arbitrary foreign prototype from a nominal display name.

I will add an explicit versioned provider ABI schema to module build metadata. This is a C storage/prototype binding, not a second semantic type graph. Each row selects an already retained exact type/signature or field ordinal and supplies its actual C declaration spelling. The generated artifact binds this schema to the complete semantic declaration digest and immutable generation. C aliases cannot change nominal identity or bypass owner/visibility checking.

The initial schema grammar is deliberately syntactic:

- A type binding supplies a declared typedef identifier from an included provider header. A record/tuple binding supplies one C member identifier for each original ordered field. Anonymous tuple fields still require an explicit mapping; I do not invent member names.
- A union binding supplies a declared typedef, discriminator member, and one declared C constant identifier and payload member path for every exact variant ordinal. Paths are sequences of member identifiers, not arbitrary injected C expressions. Flattened semantic field ordinals retain the existing variant partitions.
- An enum binding supplies its declared C typedef and exact named C constants for its semantic cases. I do not assume C enum width equals my runtime integer width or derive discriminators from declaration order.
- An opaque binding supplies its original declared C pointer typedef. Its counted semantic owner/name key remains separate. Logical pin/drop policies and issued transport tokens remain required.
- An array binding selects a defined array ABI and its actual complete element binding. Existing DynArray ABI declarations may be reused only where the actual provider prototype uses them; an arbitrary C pointer/count struct needs its own explicit generated conversion schema.
- Each function binding supplies its actual C symbol, exact retained semantic signature, and ordered C parameter/result type bindings. A generated function-pointer assignment to the declared header symbol checks the prototype at compilation. No cast suppresses a mismatch.

Scalar defaults use the existing proved storage contract only where the foreign declaration agrees: int64, double, bool, byte and borrowed C string are not interchangeable. Header typedef aliases are resolved by the C compiler, not by guessing string spellings. A header mapping is trusted native input, like the provider's C source; the semantic checks still refuse mismatched owner keys, field counts, variants or signature selectors.

I generate provider glue in the same immutable module generation as its schema and actual library. The build-context fingerprint includes the complete ABI schema and generated adapter source. The module builder owns dependency preprocessing and publication; installed source-hidden operation uses installed headers/schema and the existing explicit compiler tools, without changing the canonical NanoISA route. Generated native carriers may be used for internal values only through explicit field-wise conversion to the declared foreign storage.

Before foreign entry, the generated adapter has typed argument temporaries, complete captured-result storage and bounded owner bookkeeping. A provider-owned aggregate result needs a complete cleanup action that can dispose of its original returned root even if envelope copying refuses. A borrowed aggregate may stop copying before acquiring further nested pins; every acquired pin has a pre-reserved record. I must not lose provider ownership merely because a returned graph exceeds the envelope limit. The current conservative policy forbids both a container drop and a nested independent drop; support for distinct ownership layers requires a separately explicit proof, not an assertion that both hooks are harmless.

Implementation order is: strict owned metadata parser and build-context participation; deterministic typed glue/schema generation with compile-only prototype/layout controls; immutable image anchoring and staged attachment; shared VM/AOT value conversion; typed callback/COP transport and complete installed acceptance. Each source checkpoint must preserve old module metadata behavior when no new schema exists. No new schema or generated adapter grants authority until all consumer and lifetime checks are installed.

This is precode. I have not changed module metadata parsing, generated provider source, feature admission or the canonical driver in this checkpoint.
