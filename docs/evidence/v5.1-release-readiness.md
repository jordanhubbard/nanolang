# My v5.1.0 release-readiness baseline

I took this baseline on 2026-09-17 against
`github.com/jordanhubbard/nanolang`. It establishes explicit release scope; it
is not my final pre-tag gate.

I ran the complete open-item queries required by
`skills/release-readiness/SKILL.md`:

```sh
gh issue list --state open --limit 1000 \
  --json number,title,body,url,labels,milestone
gh pr list --state open --limit 1000 \
  --json number,title,body,url,labels,milestone
```

The issue query returned zero open issues. The pull-request query returned six
open pull requests. Only PR #414 explicitly named v5.1.0; I created the
`release/v5.1.0` label and applied it there so the scope is machine-readable.
That PR is therefore the one release-scoped blocker in this snapshot.

Draft PRs #307, #331, #343, #349 and #356 do not name v5.1.0, carry its label,
or belong to a v5.1.0 milestone. I reviewed them as visible unscoped work and
did not close them merely to make the release gate green. Their stale
integration history remains separate from this release decision.

Before I tag v5.1.0, I must rerun both complete queries, review any new or
changed item, record every triage comment, and require no release-scoped item
to remain open. This baseline does not waive that final audit.
