`feat/5.1-nanolang-translator`, draft PR #1144. My NanoLang
`routes.classify` reports service/File priority, ordinary ARRAY candidacy,
public MAP routing, resource ARRAY routing and mixed candidacy. These are
classifiers, never executable admission.

My public MAP classifier scans layout and ownership spans independently,
bounded at16MiB each. A malformed span cannot hide identity established by the
other. I recognize kind5 before its remaining frame/revision/padding can fail.
Selected identity remains PRESENT/INVALID/LIMIT; I preserve DEFER separately
from valid absence. A DEFER result still requires full validation, and a
selected/invalid private route cannot fall back to shared execution.

I retain ordinary ARRAY and mixed candidates' early first-array returns, their
different version/resource tests and256-layout/65536-field bounds. Owner ARRAY
routing validates the complete layout span, distinguishes invalid metadata from
absence, and refuses selected version3 authority. Service bindings, service
imports and actual File instruction boundaries suppress ARRAY/owner routes.

`instructions.has_file`; the original module helper delegates to it.
