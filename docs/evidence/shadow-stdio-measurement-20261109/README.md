# My shadow stdout descriptor measurement

I measure the actual non-verbose shadow path in my pinned existing local C
provider before changing it. I preserve the original ten-second supervisor,
select every shadow, require completed successful reports and execute each
actual native result. I do not establish this existing provider's current
C-source provenance or qualify the complete source compiler from this fixture.

My [declared plan](plan.json) fixes six plain/observed attempts for each size:
plain, observed, observed, plain, plain, observed. All twelve attempts complete.
The scalar fixture executes 1,283 or 5,000 counter-changing shadow bodies, then
one final shadow checks that every prior body ran and that main returns zero. Body output stays
suppressed, and the compiled native program prints zero, checking that shadow
mutations remain in the supervised child.

My [real-call analysis](analysis.json) observes, per 1,284 selected shadows,
1,284 devnull opens, 1,284 duplicates, 2,569 dup2 calls and 2,570 closes. The
final three inclusive descriptor-time sums are 0.008498, 0.012646, 0.012276 seconds.
For 5,001 selected shadows they are 0.038863, 0.038667, 0.039801 seconds.
Observer timing overhead is included. Whole CLI wall time includes native
compilation and cannot isolate a shadow-framework improvement.

My small [macOS observer](interpose.c) forwards original arguments and return
values and preserves errno around timing. It allocates no descriptor cache or
replacement evaluator. My [native controls](control.json) compare real return
values, errno, file mode/data, fork/exit status and stdout with observation
absent/present. Both pass with identical stdout. The observer emits diagnostic
records on stderr; its destructor tag does not independently observe exit
status. I use the subprocess return code and explicit child _exit records.

I retain [all samples](samples.json), [build/input/product checks](build.json),
[exact source and text records](texts.json.gz), and the [measurement driver](measure.py).
The two fixtures' hashes match their original generated bytes. All twelve
native product hashes and the provider/library hashes remain stable. The
new control executable has its own inspected build/product hash.

I leave production redirection unchanged. This local fixture does not establish
a useful whole-compiler optimization or diagnose the hosted Apple failure.
Current source execution, fresh-stage/corpus, profile budgets, carrier lifetime,
security, native lifecycle and release obligations remain open. I hold local
full provider/SDK builds while disk headroom remains below policy; this probe
uses a small library and scalar fixtures.


I retain the initial twelve successful samples and their original source/text
snapshots under `initial/`. I then strengthen the final main shadow to call
main and assert its return, in addition to the ordered counter assertion,
and execute the same twelve-sample plan again. Both generations remain retained;
I do not compare them as an optimization. All 24 actual native image hashes
remain stable, with initial images retained locally under
`.test_output/shadow-stdio-initial/`. Every final compile has empty stdout;
plain stderr is empty and observed stderr contains only probe records.
