# I retain immutable File source companions

I implement the compiler-input reader in `src/nanoisa/file_source_snapshot.{c,h}`. It resolves a counted relative document path against a retained absolute source origin, opens the final component without following symlinks, reads only bounded regular files, closes once, and delegates complete catalog validation to `nl_file_binding_prepare`. Its context owns exact read bytes, the resolved path and the strict preparer's canonical interface/binding views. Later filesystem mutation does not change retained bytes. It performs compiler input I/O, not File service execution.

I admit at most sixteen snapshots and reserve a conservative aggregate project-heap bound of 64 MiB before acquisition. The bound counts retained storage, new path/read allocations and the strict preparer's complete nested bound once. It excludes stack, allocator overhead and libc internals. Ancestor stability and valid retained source origins remain caller preconditions; this does not implement hostile ancestor-race protection. Failed acquisitions preserve previous snapshots and caller output indices. Peak-bound accounting includes failed admitted attempts.

Both integrated targets pass on Darwin: `NANO_FILE_SNAPSHOT_CC=cc make test-file-source-snapshots` and `NANO_FILE_SNAPSHOT_CC=/opt/homebrew/opt/llvm/bin/clang make test-file-source-snapshots-sanitize`. The latter freshly instruments the reader and all five strict-preparation providers with ASan/UBSan and leak detection. Controls cover exact maximum size, oversized inputs, counted NUL/invalid UTF-8, absolute/missing/symlink/FIFO/directory refusal, strict document rejection, immutable views, capacity, each reader allocation prefix, early EOF, EINTR recovery and close-after-real-close failure. Existing strict-preparer allocation coverage remains separate; these reader hooks do not claim every nested allocation prefix.

I do not yet call this reader from either source frontend. Complete namespace/nominal resolution, independent lowering, generated shadows, grants, publication, Linux qualification and the full #989/#976 scope remain open.
