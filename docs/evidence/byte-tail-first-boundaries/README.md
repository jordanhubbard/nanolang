# I retain the first byte and tail boundaries

I retain six immutable Linux qualification histories: fresh9ee compiler/bootstrap and source emitters,2a byte-array signature refresh,4fa contextual byte-array literal refresh,6a LLVM tail implementation,3e unknown-parameter correction and dbb assembler refusal-fixture correction. The reports preserve the first failure in each run. No run in this bundle establishes full backend, bootstrap, SDK or release readiness.

The4fa refresh passes original byte source, computed scalar pop and lexical authority/refusal controls, literal boundaries, enum/scalar destinations and all byte values, then stops at the old LLVM tail refusal. The corrected3e/dbb histories advance actual LLVM tail behavior; dbb passes four tail methods before generated C mutual recursion fails at O0. I correct that independent C backend boundary before another affected native execution.

Each compressed bundle retains all top-level phase reports, commands, terminal supervision, logs, source/tool/product maps and the archived driver identity. `seal.json` hashes each bundle and each member. The companion object indexes locate the immutable local CAS; every indexed object was rehashed before this publication. Their local paths are part of the evidence scope, not downloadable release assets. Inner fixture artifacts are retained at the paths printed in the logs; this bundle does not archive those directories or claim an independent audit of every inner product. The C-seed/Stage1/Stage2 binaries after9ee are explicitly reused and inventoried; these refreshes do not claim fresh later bootstraps.
